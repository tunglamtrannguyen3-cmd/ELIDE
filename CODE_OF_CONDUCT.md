# ⚡ ELIDE Code of Conduct

> **Build things. Help people. Debate ideas. Don't attack each other.**

Welcome to the ELIDE community! 🥚⚡

ELIDE is an open-source project built to make development simpler, lighter, and more enjoyable.

We want this community to be a place where people can **learn, contribute, experiment, break things, fix things, and occasionally wonder why their compiler hates them.** 💀

Whether you're an experienced developer, a beginner writing your first `Hello, World!`, or someone who accidentally deleted the wrong file at 2 AM — you're welcome here.

---

## 🎯 Our Goal

Our goal is to maintain a community where:

* 🤝 Contributors can work together respectfully.
* 🧠 Beginners can ask questions without being mocked.
* 💡 Ideas can be challenged without attacking the person proposing them.
* 🛠️ Technical discussions remain productive.
* 🌱 New contributors can learn and grow.
* 🐛 Bugs can be reported without starting a civil war.
* ⚡ People can build cool things without unnecessary gatekeeping.

ELIDE should be a place where **the code gets roasted, not the contributor.** 🔥

---

# 📜 Community Standards

Everyone participating in the ELIDE community is expected to:

### 🤝 Be Respectful

Treat other people with basic respect and courtesy.

Different experience levels, opinions, programming languages, operating systems, and workflows are normal.

Someone using a different editor does not require a declaration of war. 😭

### 🧠 Help People Learn

Not everyone knows everything.

If someone asks a question that seems obvious to you, remember that it was probably not obvious before you learned it.

Explain things when reasonably possible instead of responding with:

> "Just read the docs."

Yes, documentation is useful.

No, it is not a magical substitute for communication. 📚

### 💬 Keep Discussions Constructive

Technical disagreement is completely fine.

You may say:

* ❌ "This implementation is terrible because you're terrible."
* ✅ "This implementation could cause unnecessary allocations because..."

Attack the **implementation**, not the human behind the keyboard.

### 🧹 Stay On Topic

Please keep issues, pull requests, discussions, and community channels reasonably related to their purpose.

Spam, trolling, excessive off-topic posting, and deliberately disruptive behavior are not welcome.

---

# 🚫 Unacceptable Behavior

The following behavior is not acceptable:

* 🚫 Harassment or bullying.
* 🚫 Personal attacks.
* 🚫 Threats or intimidation.
* 🚫 Discrimination or hateful conduct.
* 🚫 Deliberately humiliating beginners.
* 🚫 Repeatedly targeting or antagonizing another contributor.
* 🚫 Doxxing or sharing private information.
* 🚫 Spam and deliberate disruption.
* 🚫 Malicious interference with project infrastructure.
* 🚫 Retaliation against someone who makes a good-faith report.
* 🚫 Deliberately fabricated reports intended to punish another person.
* 🚫 Turning every technical disagreement into a personal argument.

### 💀 Especially Important

**Do not turn GitHub Issues into boss fights.**

A pull request is not a PvP arena.

A code review is not an opportunity to establish dominance.

And a compiler error is already suffering enough. 😭

---

# 🔥 Code Reviews

Code review exists to improve code.

It does **not** exist to determine who has the largest brain.

When reviewing code:

* 🔍 Explain what could be improved.
* 💡 Suggest alternatives when possible.
* 🧠 Explain the technical reasoning behind significant criticism.
* 🤝 Assume good intentions unless there is evidence otherwise.
* 🧹 Keep criticism focused on the code.
* 🌱 Help newer contributors understand the project.

### Remember:

> **Bad code can be fixed. Making someone afraid to contribute is much harder to fix.**

---

# 🧪 Technical Disagreements

ELIDE is software.

Software involves opinions.

Therefore, disagreements will happen.

You may disagree about:

* 🦀 Rust architecture.
* 🧩 UI design.
* ⚡ Performance.
* 🧠 LSP behavior.
* 🐧 Linux distributions.
* 🛠️ Build systems.
* 📦 Dependencies.
* 📝 Naming.
* 🥚 Whether something should be called an Egg feature.

All of that is fine.

What isn't fine is turning:

> "I think this architecture is problematic."

into:

> "You're an idiot."

Debate the **idea**.

Not the person.

---

# 🐌 A Tiny Industry Roast

ELIDE has opinions.

Some of them may occasionally be expressed through jokes. 😭

We reserve the right to lovingly make fun of common software-industry habits such as:

* 🐌 Editors that need a small ecosystem just to open a text file.
* 🧱 Toolchains with seventeen layers of configuration.
* 📚 Documentation that requires documentation.
* 🔌 Software that installs 400 dependencies to display `Hello World`.
* 💾 Development environments that somehow consume more RAM than the operating system.
* 🧙‍♂️ Tools where the easiest installation method is apparently "become a wizard."

For example:

> 🐌 **ELIDE doesn't need 47 background services to open `hello.c`.**

> 🧱 **If your editor needs a 900-page manual before you can save a file, we respect your dedication. We don't understand it, but we respect it.**

> 💀 **Your IDE using more RAM than Minecraft is a feature. Probably.**

These jokes are aimed at **software and engineering practices**, not at attacking individual developers or community members.

If your favorite editor gets roasted, please remember:

**It's a joke. Your editor will survive.** 🫡

# 🔒 Privacy & Personal Information

Do not share another person's private information without their permission.

This includes:

* 📍 Addresses.
* 📞 Private phone numbers.
* 📧 Private email addresses.
* 🔑 Passwords or credentials.
* 🪪 Government identification.
* 🔐 Private account information.

Public project information is different from private personal information.

When in doubt, don't post it.

---

# 🚨 Reporting

If you experience or witness behavior that violates this Code of Conduct, please report it privately to the ELIDE maintainers.

When possible, include:

* 📝 What happened.
* 🕐 When it happened.
* 🔗 Where it happened.
* 👤 Which accounts were involved.
* 📸 Relevant screenshots or other evidence.
* 🧩 Any context that may help explain the situation.

You do **not** need to prove that a violation occurred before making a good-faith report.

### 🛡️ Security Issues

Please do **not** publicly post sensitive security vulnerabilities.

Use the project's designated security reporting method instead.

---

# ⚖️ Enforcement

ELIDE maintainers may take appropriate action when this Code of Conduct is violated.

Depending on the situation, actions may include:

1. 🟡 Private or public warning.
2. ✏️ Request to edit or remove inappropriate content.
3. 🗑️ Removal of inappropriate content.
4. 🔇 Temporary restriction or mute.
5. ⏳ Temporary ban.
6. 🚫 Permanent ban.

Actions will be considered on a **case-by-case basis**.

Severity, frequency, context, previous warnings, and impact on the community may all be considered.

Not every disagreement is a violation.

**Good-faith technical criticism is welcome.**

---

# 🧑‍⚖️ Maintainer Responsibility

Maintainers are expected to enforce this Code of Conduct fairly and consistently.

Maintainer privileges should not be used to:

* Silence legitimate criticism.
* Win personal arguments.
* Remove contributors simply for disagreeing.
* Abuse moderation powers.

Maintainer authority exists to **protect the community and keep development productive.**

---

# 🧯 False Reports

Good-faith reports are welcome, even when an investigation eventually determines that no violation occurred.

However, deliberately fabricated reports, impersonation, or attempts to weaponize moderation against another contributor may themselves be considered violations.

* 🐙 The ELIDE GitHub repository.

* 🧪 Official ELIDE projects and repositories.

# 🥚 The ELIDE Philosophy

ELIDE is supposed to make development easier.

That applies to people too.

You don't need to be the smartest person in the room.

You don't need to know every programming language.

You don't need a 20-year résumé.

You just need to be willing to **learn, build, share, and help others when you can.** ❤️

So:

> ⚡ **Build things.**
>
> 🤝 **Help people.**
>
> 🧠 **Debate ideas.**
>
> 🐛 **Fix bugs.**
>
> 🥚 **Ship software.**
>
> 🚫 **Don't attack each other.**

And if something breaks?

Don't panic.

It's probably just another Tuesday in software development. 💀
