# 🛡️ Security Policy

## 📦 Supported Versions

The following versions of ELIDE are currently supported with security updates:

| Version | Supported |
| ------- | --------- |
| 2.0.x   | ✅ Yes     |
| < 2.0   | ❌ No      |

Security support may change as new major versions of ELIDE are released.

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability in ELIDE, please report it privately rather than opening a public GitHub issue.

Please contact:

`tunglamtrannguyen3@gmail.com`

When reporting a vulnerability, please include as much of the following information as possible:

* 🔎 A clear description of the vulnerability
* 🏷️ The affected ELIDE version
* 💻 The affected operating system or environment
* 🧪 Steps to reproduce the issue
* 📎 A proof of concept, if available
* ⚠️ The potential impact of the vulnerability

Please avoid publicly disclosing the vulnerability until it has been investigated and, when appropriate, fixed.

## 🛠️ Response

I will review vulnerability reports and investigate their impact.

If the vulnerability is confirmed, I will work on a fix and release an update when practical. 🚀

Depending on the severity of the issue, additional information may be published in the project's release notes or security documentation.

## 🎯 Scope

This policy applies to security vulnerabilities affecting ELIDE itself, including:

* 🖥️ The ELIDE application
* 📦 ELIDE's source code
* 📁 ELIDE's handling of files and user input
* 🔌 ELIDE's integration with supported language servers
* ⚙️ Security-relevant build or runtime behavior

Issues in third-party dependencies should generally be reported to the respective upstream project, although relevant dependency vulnerabilities affecting ELIDE may also be reported here.

## 🧯 Security Philosophy

ELIDE follows a pretty simple philosophy:

> 🔒 **Fix the vulnerability. Don't turn it into a feature.**

No 47-step corporate ritual.
No "please upload your entire life story to continue." 💀
No "we'll get back to you in 3–5 business eternities." 🗿

Just:

```text
🐛 Find bug
   ↓
📨 Report bug
   ↓
🔬 Investigate
   ↓
🛠️ Fix bug
   ↓
🚀 Ship fix
   ↓
😌 Everyone goes home
```

### 🤨 The Verification Paradox

Some platforms have increasingly elaborate identity and age-verification systems.

Roblox, for example, currently offers facial age estimation and government-ID verification for age checking, with Persona involved in the verification process.

ELIDE's security philosophy is somewhat simpler:

> **"You found a security bug. Tell me what happened. You don't need to submit your passport to report a buffer overflow."** 💀

And yes:

> 🔐 **Security should protect users — not make users wonder what data they had to hand over just to prove they're users.**
